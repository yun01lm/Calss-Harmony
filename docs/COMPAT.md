# 与 Android 版的行为差异

行为规格以 [Calss-Android](https://github.com/yun01lm/Calss-Android) 为准。
**只有在本文件里登记过的差异，才算"有意为之"**；没登记的不一致都按 bug 处理。

---

## 1. 作息解析：全部认不出时，把具体原因也报出来

| | Android 版 | 鸿蒙版 |
|---|---|---|
| 场景 | 一张作息表截图，里面**所有**时间都非法（或全是课间行） | 同左 |
| 行为 | 只返回一句"没能从图片里认出作息时间，可以在下面手动添加节次"，而"有 N 处时间不合法""有 N 行是课间"这些**已统计到的原因被丢弃** | 先列出已统计到的原因（重复 / 时间不合法 / 课间行数），再给出上面那句兜底提示 |
| 位置 | `ocr/TimetableTextParser.kt` 的 `if (found.isEmpty())` 分支 | `logic/TimetableTextParser.ts` 同名分支 |
| 理由 | —— | 用户看到"认不出"时最需要知道的是**为什么**（是截图截错了，还是时间格式怪？）。丢原因等于让人无从下手。断言见 `tests/timetable-text-parser.test.ts` → "非法时间（开始晚于结束）被忽略并提示" |

## 2. 数据库打开：没有 Room 的 schema 校验，改用"状态判断 + 演练"

| | Android 版 | 鸿蒙版 |
|---|---|---|
| 机制 | Room 在打开库时把实体推导出的 schema 与实际表逐列比对，不一致直接抛 `IllegalStateException` | `relationalStore` 没有等价校验，SQL 写错只有运行时才知道 |
| 补法 | —— | ① 建库/迁移全部是**一份可在 Node 上跑的真 SQL 步骤清单**（`tests/bootstrap.test.ts`、`tests/sql.test.ts`，共 33 条断言）；② 打开库时按「版本号 × 现有表」分成 fresh / upgrade / repair / noop 四态，遇到矛盾（版本 0 但只有一半的表、版本高于支持）**直接报错拒绝打开**，不猜、不删；③ 写入版本号后**回读校验**；④ 设备上用 `platform/MigrationProbe.ts` 造 v1 库跑一遍真机迁移 |

## 3. 建库/迁移失败时的表现

| | Android 版 | 鸿蒙版 |
|---|---|---|
| 迁移中途失败 | Room 事务回滚，进程崩溃（用户看到闪退） | 事务回滚 + 抛出带原因的错误，页面显示「数据库失败：…」而不是闪退 |
| 理由 | —— | 课表打不开时，一句能读的错因比闪退有用 |
| 重试 | Room 靠版本号，重跑会再崩一次 | **整套迁移可重跑**：`CREATE IF NOT EXISTS`、`INSERT ... WHERE NOT EXISTS`、`INSERT OR IGNORE`，ALTER 按 `pragma_table_info` 决定加不加；另有 `repair` 分支（表已是 v2 但版本号还是 1 → 只补版本号）。见 `docs/REVIEW.md` 的 H-1 |
| 回填 | Room 迁移里直接 `SET timetableId = 1` | 只回填 `WHERE timetableId = 0` —— 否则重跑会把用户后来建的第 2、3 张课表的课全搬回第 1 张 |

## 4. 外键级联：鸿蒙上**关着**，所以一律显式删

| | Android 版 | 鸿蒙版 |
|---|---|---|
| 删课表/删课 | 靠 `ON DELETE CASCADE` 连带清 `course_schedules` | **显式 `DELETE FROM course_schedules WHERE ...`** |
| 依据 | Room 打开库时会 `PRAGMA foreign_keys = ON` | 设备实测 `PRAGMA foreign_keys = 0`（`docs/evidence/14-probe-fk.jpeg` 第一行）。关系型库默认就是 OFF |
| 后果 | —— | 若照抄 Android 的写法，删课表后会留下一堆孤儿时段；新建课程一旦复用到同一个 id，就会"借尸还魂"出现在别的课表里 |
| 断言 | —— | `tests/store.test.ts` 的删除用例**故意不开外键**（`SqliteRunner.open({ foreignKeys: false })`），证明清得干净 |

## 5. 周次掩码：JS number 只有 53 位安全整数

| | Android 版 | 鸿蒙版 |
|---|---|---|
| 存储 | SQLite INTEGER（64 位）+ Kotlin `Long`，理论上 64 周 | 同一列、同一类型，但 `getLong()` 返回 **JS number**，超过 2^53 会丢精度 |
| 本应用实际范围 | 周数夹在 1..30 | 同左（`clampTotalWeeks`），远在安全范围内 |
| 兜底 | —— | `maskToDb` / `assertSafeMask`：越界**直接抛错**，而不是安静存进一个错的周次（`tests/store.test.ts` 有断言） |

## 6. 与平台相关、不算差异的部分（说明以便对照）

| 主题 | Android | 鸿蒙 |
|---|---|---|
| 长度/字号单位 | `dp` / `sp` | `vp` / `fp`（算法逻辑一致，见 `logic/CellLayout.ts`） |
| 周次掩码类型 | `Long`（64 位） | `bigint`（语义等价；交界处 `BigInt()`/`Number()` 转换） |
| 日期运算 | `java.time.LocalDate` | **epochDay 整数**（不直接用 `Date`，规避时区/夏令时） |
| 程序化翻页 | `PagerState.animateScrollToPage` | `SwiperController.changeIndex`（两者都会触发回调，抑制规则一致） |
| 数据库存储位置 | `context.getDatabasePath("calss.db")` | relationalStore 沙箱（`databaseDir/rdb/`），库名同为 `calss.db` |
| 库版本号 | Room `version = 2` | SQLite `user_version = 3`（v3 = 每次上课各自的教室；v2 之前与 Android 同构） |

## 7. 课程编辑：保存按钮在顶栏，软键盘盖不住

| | Android 版 | 鸿蒙版 |
|---|---|---|
| 面板布局 | `AlertDialog` 底部按钮（`confirmButton`），系统负责把对话框抬到键盘上方 | 自绘底部面板：**「取消 / 保存」放顶栏**，主按钮不再放面板底部 |
| 理由 | —— | 自绘面板高度固定（76%），软键盘弹出时不会自动上推，底部的按钮直接被盖住。实测模拟器上输完课程名后点不到「保存」（`docs/evidence/32-course-editor.jpeg`） |

## 8. 三处"顺手补齐"的交互（Android 版没有，本版新增）

| 行为 | 为什么加 |
|---|---|
| 保存课程后，若**当前这一周没有这门课**，自动跳到它第一次出现的那一周 | 把周次改成 `5-6` 而人停在第 1 周时，保存后界面毫无变化，看起来像"没保存上"（实测就是这样）。跳一下比弹个提示更直接 |
| 翻周（箭头或滑动）时**自动收起详情卡** | 卡片描述的是上一周的某门课，留着会让人以为这门课在这一周 |
| 课程编辑面板的**删除要按两次**（第一次变红、文案改成"再按一次删除这门课"） | 删除不可撤销；两次点击比一个系统确认框更省事，也避免手滑 |

## 9. 导入时的"按课程归并"放在哪一层

| | Android 版 | 鸿蒙版 |
|---|---|---|
| 归并位置 | `pdf/SchedulePdfParser.kt` 的 `merge()`：解析完立刻按「名称+教师+地点」合并 | `data/CourseMerge.ts` 的 `mergeCourseItems()`，由 `Index.onImportPayload` 调用，`ScheduleStore.mergeCourses/replaceCourses` 内部再兜一次 |
| 为什么必须做 | —— | 两个解析器都是**按格子/按段落**输出：一门课一周上两次就是两条 `RawCourse`。不归并会写成 **2 条课程行** —— 改一门只改一半、删一门只删一半，合并导入还会永远更新不到另一条（`docs/REVIEW.md` 的 H-2） |
| 副产品 | 无 | 一个时段都认不出（周次掩码 = 0）的课会被**丢掉并报出课程名**，而不是存进库里变成"所有周都看不见的课" |
| 已知限制 | 同一门课两次上课**地点不同**时合并不到一起（`location` 在 Course 上，不在每次时段的 `course_schedules` 上） | **v3 已解决**：教室跟着时段走（`course_schedules.location`），合并键改成「名称+教师」。真实课表 22 条格子 → 14 门课，其中"算法分析与设计"就是 1 门课 2 个时段（周一 404 / 周三 137） |

## 10. 保存课程的写库顺序

| | Android 版 | 鸿蒙版 |
|---|---|---|
| 顺序 | Room `@Transaction` 方法里整体替换时段 | **先校验全部掩码，再在一个 `runSteps` 事务里 UPDATE + DELETE + INSERT** |
| 反面 | —— | 第一版是先 `exec(DELETE)` 再循环 `assertSafeMask`：周次一不合法就抛错，而旧时段已经删了 —— 一门课凭空变成"没有时间"，界面上直接消失（`docs/REVIEW.md` 的 H-1） |
| 新建路径 | —— | 自增 id 拿不到事务外，失败时**补偿删除**课程行；更新路径先确认目标行存在（外键关着，UPDATE 0 行不报错） |

## 11. 真实课表里的"学分折行"（用第二份真实 PDF 验出来的）

| | Android 版 | 鸿蒙版 |
|---|---|---|
| 现象 | —— | 网格式单元格的信息块以 `…/总学时:16/学分` 结尾，**学分值被折到下一行**成一个孤立的 `:1.0`。解析器把它当成下一门课的"课名首行"，课名变成 `:1.0算法分析与设计`；课名一脏，"按名称归并"也跟着失效 —— 同一门课的两次课变成两门课（真实课表 22 条里 7 条被污染） |
| 修法 | —— | `GridFormatParser.looksLikeTail` 增加"纯数值尾巴"判定（`分:4.0`、`学分:3.0`、`:80`）；`ParsingUtils.cleanName` 再兜一道，剥掉 `[学分/学时…]?:数字` 这种前缀 |
| 验证 | —— | 同一份 PDF：修前 19 门（含 7 个脏名）→ 修后 **18 门、课名全干净**，且"概率论与数理统计"在编辑器里是**一门课两个时段**（周二 1-2、周四 3-4），与 Android 的 merge 结果一致 |
| 反向保护 | —— | `英语:听力`、`体育Ⅲ-网球`、`3D打印` 这类正常名字一个字都不动（`tests/pdf-parsers.test.ts` 有断言） |

> 新增差异时请在此追加一节，并在对应测试里留下断言。

## 12. 合并键：地点不参与（v3），教学班参与（v4）

| | Android 版 | 鸿蒙版 |
|---|---|---|
| 合并键 | 名称 + 教师 + 地点 | **名称 + 教师 + 教学班**（地点跟着每条时段走，不参与） |
| 为什么不含地点（v3） | —— | 真实课表里一门课一周上两次、两次在不同楼是常态（"数字电子技术基础"周一 301、周五 107）。带上地点会把这种课拆成两门：改一门只改一半、删一门只删一半 |
| 为什么含教学班（v4） | —— | 只按"名称+教师"会走向另一个极端：同一位老师带两个班、课名相同时，那是两门**不同**的课，并成一门后**删一门会把另一门一起删掉**。教学班跟着时段存（`course_schedules.classGroup`），两边就都分得清 |
| 教学班从哪来 | —— | 抓详情里形状像班级的那一段（切成 `;、,` 后每段都以「班」结尾）。真实 PDF 里它是第 5 段（第 4 段是「课名-课程代码」）；列表式则取「教学班组成」/「教学班」 |
| 认不出时 | —— | `classGroup` 留空 → 退回 v3 的「名称+教师」。宁可少分（同一门课多时段仍然合并），也不把课名/备注误当班级 |
| 升级 | —— | v2→v3：加 `location` 并用课程的教室回填；v3→v4：加 `classGroup`（无需回填）。v1 的库一次跑完 v1→v2→v3→v4，每步都可重跑。与 Android 的库不再同构，跨平台迁移需要额外映射（目前没做） |

## 13. 自定义安排的编辑（最后一块功能）

| | Android 版 | 鸿蒙版 |
|---|---|---|
| 入口 | 点空格 → 先问"课程还是自定义安排"；点已有色块 → 详情卡右上角「编辑」 | 同左（`pages/Index.ets` 的 `addChoiceCard` / `detailCard`） |
| 表单 | 标题、备注、星期、起止节、周次；`AlertDialog` 底部按钮 | 同一组字段，自绘底部面板、保存放顶栏（与课程面板一致，见第 7 节） |
| 周次默认值 | 硬编码 `1-20` | **按当前课表的总周数**生成（`EventDraft.defaultWeeks`）：20 周学期与 Android 完全一致，18 周学期则默认 `1-18` —— 否则新建的安排在后两周"凭空消失" |
| `color` / `startMinute` / `endMinute` | 界面不编辑，保存时 `loaded.copy(...)` 保留 | 同（`eventColor` / `eventStartMinute` / `eventEndMinute` 透传）。这三个字段没有 UI，但**编辑一次就被清空**是不可接受的 |
| 只有钟点、没有节次的安排 | `startPeriod ?: 1`，保存后落进第 1 节 | 同。网格的纵轴就是节次，没有节次的安排画不出来（`logic/WeekItems.ts` 里显式跳过），编辑时让它落进网格比继续藏着合理 |
| 删除 | 表单里一个「删除该安排」，点一下立即删 | 点两下（第一下变红、文案改成"再按一次删除这条安排"），与课程面板一致 |
| 详情卡 | 时间（节次 + 作息里的钟点）、备注 | 时间（节次 + 钟点）、**周次**、备注、冲突提示；右上角「编辑」 |
| 出错提示 | 红字在字段下方 | 同，并且**只标红出错的那一格**（`EventDraftResult.badField`）—— 标题空着却把周次框标红，会让人一直改那个没错的格子 |
| 输入规则 | `InputNorm.weeks` 规范化、星期/节次夹取 | 同一个函数（`logic/EventDraft.ts` 复用 `CourseDraft` 的夹取与 53 周存储上限），断言见 `tests/event-draft.test.ts` |
| 保存后跳周 | 无 | 与课程一致：保存的安排在当前这一周看不见时，自动跳到它第一次出现的那一周 |
